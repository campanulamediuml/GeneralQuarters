General Quarters API

版本0.1.0 · 下载OpenAPI文档 · 返回游戏 · 完整字段与语义见仓库根目录的API.md（本页只是速查表）

约定

  • 会话由创建/加入接口写入HttpOnly Cookiegq_session；除健康检查与文档外都要带。
  • 错误一律是{"error":"人类可读说明"}；成功是JSON。
  • hex坐标为ABCD：AB行、CD列，例如0203。
  • base_turn可选：提交时看到的回合号，只有"回合已结算"的过期提交会被409拒绝，不比对版本号。
  • command_id由客户端生成、玩家范围内唯一；断线重试必须沿用原ID。
  • 房间闲置12小时且无人在线时只释放内存，库里的房间、事件与回合快照全部保留，下次访问自动重载。

HTTP（大厅 + 脚本兜底）

方法路径用途
POST/api/v1/rooms创建房间，body可含name、scenario_id、solo、faction
POST/api/v1/rooms/join凭token加入，body含token、name
GET/api/v1/rooms/{id}/state当前玩家私有快照（含phase、weather_cells等）
GET/api/v1/rooms/{id}/events最近100条可见事件
POST/api/v1/rooms/{id}/commands提交一条命令（进房后网页改走WebSocket）
POST/api/v1/rooms/{id}/ready就绪；回执{accepted,turn}

命令与回合

POST /api/v1/rooms/{id}/commands
{"command_id":"唯一ID","base_turn":3,"type":"SET_MOVE","unit_id":"a-flag","coord":"0203"}

POST /api/v1/rooms/{id}/ready
{"base_turn":3,"ready":true}

CLEAR_MOVE等撤回类命令结构相同但不需要coord。state.phase == "deploy"时是开局部署：SET_MOVE只受部署区限制、立即生效且没有冷却；双方都ready才开战（phase变battle，回合号仍是1）；部署阶段允许ready:false撤回，任何部署动作也会自动撤回ready。开战后ready不可撤销，所有玩家ready即同步结算并提升turn。

WebSocket

连接GET /ws，用同一会话Cookie；观战用?mode=spectator，连上后10秒内发订阅帧{"type":"subscribe","room_id":"…","token":"…"}。进房后的状态读取、命令、ready都走这条连接，不再轮询。

请求  {"type":"rpc_request","id":"1","method":"POST","path":"/api/v1/rooms/{id}/commands","body":{…}}
应答  {"type":"rpc_response","id":"1","status":200,"body":{…}}
推送  {"type":"state","patch":{…}}      // 增量，按字段合并
      {"type":"snapshot","view":{…}}    // 全量底座（首帧/重连/观战）

服务端每30秒ping一次，90秒没有pong即断开；单帧上限1MB。补丁只带变化的节点，实体列表按id合并，客户端不能把补丁整块赋值给数组。

AI扩展边界

DeepSeek适配器在服务器内运行：模型只接收当前阵营的私有视图和对话，输出候选结构化命令；候选命令仍走同一套校验与回合引擎。API密钥不进入浏览器，自然语言不能直接改变游戏状态。
