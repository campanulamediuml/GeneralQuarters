General Quarters API

版本 0.2.0 · 下载 OpenAPI 定义 · 返回游戏

本页是速查表。完整命令、快照字段和补丁语义见仓库根目录的 API.md。

约定

  • 创建或加入房间后，玩家使用 HttpOnly Cookie gq_session；观战使用房间 join_token。
  • 成功响应为 JSON；错误为 {"error":"说明"}，可另带 error_code 和 error_params。
  • 请求体会拒绝未知字段。hex 坐标为 ABCD：AB 行、CD 列，例如 0203。
  • base_turn 大于 0 时必须等于当前回合。command_id 在同一玩家范围内唯一，重试必须沿用原 ID 和请求体。
  • 闲置 12 小时且无玩家在线的房间只释放内存，不删除数据库记录；后续访问会自动重载。

HTTP（仅大厅与观战 token 解析）

方法路径用途
GET/healthz健康检查
POST/api/v1/rooms创建房间；body 可含 name、scenario_id、faction、solo
POST/api/v1/rooms/join凭 token 加入；body 含 token、name
GET/api/v1/watch/{token}解析观战 token，返回 room_id

命令与回合

以下 JSON 是 WebSocket RPC 的 body；对应 HTTP 房间接口已删除。

命令  {"command_id":"唯一ID","base_turn":3,"type":"SET_MOVE","unit_id":"a-flag","coord":"0203"}
就绪  {"base_turn":3,"ready":true}

战斗阶段的 SET_MOVE 只登记规划，回合结算才移动；整编、拆分和非无线电航空命令立即修改状态。无线电 RECALL_AIR、RETASK_AIR、RETARGET_AIR 在结算时判定。CLEAR_MOVE 用 unit_id 撤销移动规划，或用 task_id 撤销无线电规划。

玩家 ready 后所有命令都会锁定。战斗阶段不允许 ready:false；部署阶段可用它撤销部署完成，但部署命令不会自动取消 ready。双方都完成部署后进入 battle，回合仍为 1。双人房必须两名玩家都到齐并 ready，单人沙盒由唯一玩家推进。

PREPARE_AIR 已废弃并返回 400；手动上甲板使用 LIFT_TO_DECK。

WebSocket RPC

玩家用同一会话 Cookie 连接 GET /ws。进房后的状态、事件、命令和 ready 只能走这条连接，没有房间 HTTP 降级接口。

请求  {"type":"rpc_request","id":"1","method":"GET","path":"/api/v1/rooms/{id}/state"}
应答  {"type":"rpc_response","id":"1","status":200,"body":{…}}
推送  {"type":"state","patch":{…}}

玩家连接和每次重连都必须先 GET state 建立全量底座，之后才能合并 state.patch。

观战

连接 GET /ws?mode=spectator，10 秒内发送：

{"type":"subscribe","room_id":"…","token":"XXXX-XXXX-XXXX"}
首帧  {"type":"snapshot","view":{…}}
补丁  {"type":"snapshot","patch":{…}}

补丁与心跳

  • 普通对象递归合并；标量和普通数组整块替换。
  • 实体数组使用 {"upsert":[…],"remove":[…]}；upsert 要就地合并。主键依次识别 id、unit_id、task_id、carrier_id、fleet_id、coord。
  • 字符串键 map 的删除使用 {"set":{…},"remove":[…]}。null 是业务值，不表示删除。
  • 服务端每 30 秒 ping，90 秒未收到 pong 断开；单帧上限 1 MiB，发送队列 32 帧。
  • 底座缺失、合并失败或跳帧时，应重连并重新获取全量，不要继续应用补丁。
